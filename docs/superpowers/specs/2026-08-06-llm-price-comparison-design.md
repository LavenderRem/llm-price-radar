# 大模型价格对比站设计规格

## 1. 项目概述

### 1.1 产品定位

“模型价签”是面向中文开发者、产品负责人和技术采购人员的大模型 API 价格对比工具。产品帮助用户在统一计价口径下查询不同服务商的模型价格、比较候选模型，并按照实际调用量估算月度成本。

产品首版聚焦“价格选型”，不承担通用大模型百科、社区评分或完整 Benchmark 排名功能。

### 1.2 用户目标

用户进入网站后，应能快速完成以下任务：

1. 找到某个服务商或模型的当前公开价格。
2. 按服务商、能力、上下文窗口和价格区间筛选模型。
3. 并排比较最多三个模型。
4. 根据业务调用量估算每月成本。
5. 查看价格的官方来源、核验日期和历史变化。

### 1.3 成功标准

- 用户在三次操作内找到目标模型或目标服务商。
- 用户可以在不登录的情况下完成筛选、对比和成本估算。
- 所有价格均展示原始计价信息、统一折算结果、官方来源和核验日期。
- 对于缓存、Batch、阶梯价等特殊规则，界面不以单一数字掩盖适用条件。
- 桌面端完整呈现方案 1 的高密度数据表；移动端保留核心查询、对比和估算能力。

## 2. 已确认的视觉方向

采用第一套视觉方案：浅色、高信息密度的“价格雷达”式分析界面。

视觉原则如下：

- 以白色和浅冷灰为主要表面，使用深蓝、亮蓝和青绿色强调关键状态。
- 主体是可扫描的数据表，不使用营销型大幅首屏。
- 通过间距、对齐、字重和分隔线建立层级，阴影仅用于浮层。
- 价格使用等宽或表格数字样式，保证纵向比较稳定。
- 右侧对比清单在桌面端固定展示；小屏幕改为抽屉或全屏面板。
- 不依赖颜色表达涨跌、最优或异常状态，必须同时提供文字或图标说明。

## 3. 首版范围

### 3.1 初始服务商

首版覆盖以下六类官方 API 服务：

- OpenAI
- Anthropic
- Google Gemini API
- DeepSeek
- 阿里云百炼（通义千问）
- 智谱开放平台

实施时以官方仍在售、具备明确公开价格的主流文本或推理模型为准。每个服务商优先收录代表性的高性能、均衡和低成本模型。图片、音频、视频生成等按张、秒或分钟计费的模型暂不进入统一 Token 价格主表，以避免不可比的单位混用。

### 3.2 首版功能

首版包含：

- 模型价格总表
- 搜索、筛选和排序
- 最多三个模型的并排对比
- 成本估算器
- 模型详情
- 价格更新记录
- 计价方法说明
- 可分享的对比链接

### 3.3 暂不包含

- 用户账号、收藏同步和团队空间
- 用户评论或社区评分
- 自定义综合能力评分
- 完整 Benchmark 榜单
- 用户提交价格
- 无人工复核的自动抓价与自动发布
- 企业合同价、区域私有报价和未公开折扣

## 4. 信息架构

### 4.1 主要视图

| 视图 | 目标 | 核心内容 |
| --- | --- | --- |
| 价格对比 | 查找、筛选并选择模型 | 筛选栏、价格表、右侧对比清单 |
| 成本估算 | 按业务用量计算月成本 | 用量输入、模型成本明细、总成本 |
| 更新记录 | 判断数据是否新鲜 | 新增模型、调价、下线、核验记录 |
| 计价说明 | 解释统一口径 | Token、汇率、缓存、Batch、阶梯价说明 |

模型详情以可链接的侧边抽屉呈现。用户从价格表进入详情后不丢失筛选条件；直接打开详情链接时，也能获得完整信息。

### 4.2 URL 状态

以下状态应写入 URL，便于刷新、返回和分享：

- 当前搜索词
- 服务商和能力筛选
- 排序字段与方向
- 币种
- 已选对比模型
- 当前详情模型

成本估算中的调用量默认只保存在浏览器本地，不写入分享链接，避免无意暴露业务规模。用户主动点击“分享估算”时，再生成包含估算参数的链接。

## 5. 功能设计

### 5.1 模型价格总表

默认列：

1. 服务商与模型
2. 能力标签
3. 上下文窗口
4. 输入价格
5. 输出价格
6. 缓存输入价格
7. Batch 优惠
8. 有效价格提示
9. 官方来源

交互规则：

- 表头支持排序，价格默认按标准输入价升序或按推荐顺序展示。
- 价格统一显示为“每百万 Token”，同时保留原始币种和原始计价单位。
- 阶梯价不能只显示最低档价格；表格展示起始价并标记“阶梯计价”，详情中列出完整区间。
- 暂无公开价格的字段显示“未公开”，不得显示为零。
- 已下线模型默认隐藏，但可在更新记录和历史详情中访问。
- “性价比最佳”仅能基于当前筛选条件和明确的价格公式，不得暗示能力排名。

### 5.2 搜索、筛选与排序

支持：

- 按服务商或模型名称搜索
- 按服务商多选
- 按文本、多模态、推理、Embedding 等能力筛选
- 按上下文窗口范围筛选
- 按输入价、输出价或综合调用价排序
- 切换人民币与美元显示
- 仅显示具有缓存价格或 Batch 价格的模型

综合调用价必须明确展示默认权重。首版默认采用输入 70%、输出 30% 的成本权重，仅用于排序；用户可以切换到成本估算器使用真实用量。

### 5.3 多模型对比

- 最多同时选择三个模型。
- 桌面端在右侧固定展示选择清单；移动端使用底部入口打开全屏对比面板。
- 达到上限后，继续选择时给出明确提示，并允许直接替换现有模型。
- 对比内容包括标准输入、标准输出、缓存输入、Batch、上下文窗口、能力、计费条件和核验时间。
- 对比结果可以生成 URL，并复制给其他人打开。
- 对比模块不生成未经数据支持的“综合胜者”。

### 5.4 成本估算器

用户输入：

- 每月请求数
- 每次平均输入 Token
- 每次平均输出 Token
- 缓存命中率
- Batch 请求占比
- 可选的上下文长度档位

基础公式：

```text
月输入 Token = 每月请求数 × 每次平均输入 Token
月输出 Token = 每月请求数 × 每次平均输出 Token
普通输入 Token = 月输入 Token × (1 - 缓存命中率)
缓存输入 Token = 月输入 Token × 缓存命中率
月成本 = 普通输入成本 + 缓存输入成本 + 输出成本
```

若模型不支持缓存或 Batch，相应比例按标准价格计算，并在结果旁说明。若服务商的 Batch 对输入和输出采用不同折扣，必须分别计算。阶梯价格根据用户输入的上下文长度或用量选择对应档位。

结果展示：

- 每个模型的输入、缓存和输出成本明细
- 预计月总成本
- 相对当前基准模型的差额和百分比
- 所用价格版本、汇率和核验日期

### 5.5 模型详情

详情包含：

- 服务商、模型名称和模型 ID
- 能力与上下文窗口
- 标准输入和输出价格
- 缓存、Batch、长上下文、推理 Token 等特殊计费规则
- 原始价格和统一折算价格
- 官方价格页面链接
- 最近核验日期
- 价格历史
- 已知限制或不适用范围

### 5.6 更新记录

更新类型：

- 新增模型
- 价格上涨
- 价格下降
- 计费规则变化
- 模型更名或别名变化
- 模型下线
- 仅核验、价格未变

记录支持按服务商和更新类型筛选。每条记录包含发生日期、核验日期、变化摘要和官方来源。

### 5.7 计价说明

必须解释：

- 为什么统一折算为每百万 Token
- 原始价格与折算价格的关系
- 人民币和美元汇率来源、日期与精度
- 输入、输出、缓存和 Batch 的含义
- 阶梯价格与长上下文加价的处理方法
- 推理 Token 是否计入输出价格
- 不同模态计价为何暂不直接比较
- “以服务商官方页面为准”的免责声明

## 6. 数据设计

### 6.1 数据实体

#### 服务商

- `id`
- `name`
- `region`
- `officialPricingUrl`
- `billingCurrency`

#### 模型

- `id`
- `providerId`
- `displayName`
- `apiModelId`
- `capabilities`
- `contextWindow`
- `status`
- `releasedAt`
- `retiredAt`

#### 价格版本

- `id`
- `modelId`
- `effectiveAt`
- `verifiedAt`
- `currency`
- `unit`
- `inputPrice`
- `outputPrice`
- `cachedInputPrice`
- `cacheWritePrice`
- `batchInputPrice`
- `batchOutputPrice`
- `tiers`
- `conditions`
- `sourceUrl`

#### 汇率版本

- `baseCurrency`
- `quoteCurrency`
- `rate`
- `effectiveAt`
- `source`

### 6.2 数据发布策略

首版采用人工核验、静态数据发布：

1. 从服务商官方价格页面收集数据。
2. 以结构化数据文件保存原始计价和适用条件。
3. 通过校验脚本检查单位、必填字段、时间和重复 ID。
4. 人工复核差异后发布。
5. 保留上一价格版本，用于更新记录和历史趋势。

该方式比直接自动抓取更适合首版，可降低页面结构变化、区域差异和促销价格导致的错误。未来可以增加自动检测，但任何价格变化仍需人工确认后发布。

## 7. 技术方案

### 7.1 前端结构

采用适合 Sites 部署的单页前端应用，首版不依赖登录或业务数据库。

建议模块边界：

- `pricing-data`：加载并校验模型、价格和汇率数据
- `pricing-normalizer`：统一单位、币种和阶梯价格
- `pricing-calculator`：执行成本估算
- `catalog-filters`：搜索、筛选与排序
- `comparison-state`：管理最多三个候选模型及 URL 状态
- `pricing-table`：渲染价格总表
- `model-detail`：渲染模型详情抽屉
- `updates-view`：渲染价格更新记录

计算逻辑应与界面组件分离，以便独立测试价格折算和成本公式。

### 7.2 状态与持久化

- 筛选、排序、币种和对比模型保存在 URL。
- 成本估算参数保存在浏览器本地存储。
- 数据文件随站点版本发布，不在用户浏览器中修改。
- 不采集或上传用户输入的业务调用量。

### 7.3 Sites 部署

实施完成后先在本地预览并完成视觉和交互验证，再使用 Sites 创建并部署站点。Sites 部署不得重新初始化或替换已验证的 Product Design 项目。

## 8. 异常与边界状态

- 数据加载失败：展示重试按钮和最近成功数据版本，不显示空白表格。
- 筛选无结果：说明哪些筛选条件导致无结果，并提供清除筛选入口。
- 官方价格缺失：显示“未公开”，禁止按零价格参与排序或估算。
- 汇率缺失：保留原始币种，停止折算并说明原因。
- 阶梯条件不完整：不输出单一估算结果，要求用户补充上下文档位。
- 模型已下线：详情保留历史标记，但不能加入新的成本对比。
- 对比链接包含未知模型：忽略未知项，同时告知用户链接中的部分模型已不可用。
- 数值过大：采用高精度十进制计算，显示时再格式化，避免浮点误差。

## 9. 响应式与无障碍

- 桌面宽度大于等于 1200 像素时展示完整表格和固定右侧清单。
- 中等宽度下隐藏次要列，通过详情查看完整计费规则。
- 移动端采用模型摘要列表；筛选和对比使用全屏抽屉。
- 所有交互支持键盘操作并具有可见焦点。
- 表格具有正确的标题、列头和排序状态语义。
- 图标按钮必须提供文字标签或无障碍名称。
- 涨跌、最佳值和异常状态不能只通过颜色表达。
- 正文和关键控件满足 WCAG AA 对比度要求。

## 10. 验证与测试

### 10.1 数据测试

- 每个在售模型至少存在一个有效价格版本和官方来源。
- 所有价格单位可转换为每百万 Token。
- 时间区间不重叠，当前价格版本唯一。
- 下线模型不会出现在默认模型表中。

### 10.2 计算测试

- 标准输入和输出成本计算正确。
- 缓存命中率为 0%、部分命中和 100% 时结果正确。
- Batch 占比为 0%、部分使用和 100% 时结果正确。
- 不支持缓存或 Batch 的模型正确回退到标准价格。
- 阶梯价在边界值前后选择正确档位。
- 人民币与美元切换不会改变底层原始价格。

### 10.3 交互测试

- 搜索、筛选、排序可以组合使用。
- 对比选择不能超过三个模型。
- 刷新和浏览器前进、后退不会丢失 URL 状态。
- 分享链接可以恢复相同的对比结果。
- 详情抽屉关闭后恢复原来的表格位置和筛选状态。

### 10.4 视觉测试

- 使用已选方案 1 作为源视觉，与实现截图进行同尺寸对比。
- 检查表格列对齐、数字字宽、固定清单、焦点状态和空状态。
- 覆盖桌面、平板和移动端关键视口。
- 不允许出现文本裁切、横向溢出、不可读的小字号或依赖悬停才能访问的核心功能。

## 11. 首版验收标准

首版达到以下条件即可进入 Sites 部署：

1. 六个目标服务商均有经过人工核验的代表模型数据。
2. 模型表支持搜索、筛选、排序和人民币/美元切换。
3. 用户可以选择三个模型并恢复或分享对比状态。
4. 成本估算支持输入、输出、缓存和 Batch 条件。
5. 模型详情展示特殊计费条件、官方来源和核验日期。
6. 更新记录能够呈现新增、调价和下线事件。
7. 关键计算逻辑通过自动化测试。
8. 实现与方案 1 的视觉方向完成对照检查。
9. 桌面和移动端核心流程可用并满足基础无障碍要求。
10. 本地验证通过后，使用 Sites 完成部署并返回可访问链接。
